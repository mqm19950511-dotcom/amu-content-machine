# Content Lessons

Append-only. Every entry is a mistake the machine made once and must never repeat.

Entries are added by `/lessons` **only after the user explicitly approves them**. Never
rewrite or prune this file unless asked directly.

Format:

```
## YYYY-MM-DD — <short rule>
**What I did:** <the specific thing in the draft>
**What the user changed it to:** <the actual edit>
**Generalizable rule:** <what to do differently every time>
```

---

## Seed rules

These ship with the system. They're the failure modes common to every voice.

## 0000-00-00 — Never open with context the reader didn't ask for
**What I did:** Started with "In the world of content creation, standing out is harder than ever."
**What the user changed it to:** Deleted it. Started at the second paragraph.
**Generalizable rule:** The first sentence should contain a specific — a number, a name, a
moment, or a claim someone could disagree with. Never a scene-setting generality. If the draft
still reads fine with sentence one deleted, delete it.

## 0000-00-00 — Never use "It's not just X, it's Y"
**What I did:** "This isn't just a workflow — it's a way of thinking."
**What the user changed it to:** "This is a workflow."
**Generalizable rule:** The construction inflates without adding information. State the thing.
If both halves are true, pick the more specific one and cut the other.

## 0000-00-00 — Don't invent specifics to make a point land
**What I did:** Wrote "we saw a 3x improvement" when the transcript never mentioned a number.
**What the user changed it to:** Removed the claim entirely.
**Generalizable rule:** Every number, name, date, and quote comes from the transcript or the
input files. If a sentence needs a specific to work and you don't have one, write
`[NEEDS: specific number for X]` and leave it for the user.

## 0000-00-00 — Don't smooth dictated speech into business English
**What I did:** Turned "and I was like, this is completely broken" into "I recognized a
significant deficiency in the process."
**What the user changed it to:** Back to roughly the original.
**Generalizable rule:** Remove filler ("um", "you know", false starts). Keep register, slang,
contractions, and sentence fragments. The user's phrasing *is* the voice — that's the entire
reason the interview step exists.

## 0000-00-00 — Don't close with a rhetorical question
**What I did:** Ended with "So what's stopping you from building your own?"
**What the user changed it to:** Ended on the last declarative sentence.
**Generalizable rule:** Close on the strongest statement, not an engagement-bait prompt.
Only ask a question at the end if the user asked one in the interview.
